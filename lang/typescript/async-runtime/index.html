JavaScript：非同期処理とイベントループ

Promise・await・CPU処理・キャンセル・同時実行数を分けて考える。

更新: 2026-09-06

JavaScript の async は「別スレッドで実行する」という指定ではない。Node.js の通常の JavaScript 処理はイベントループのスレッドで動き、重い計算をすると他のリクエストの処理も遅れる。

待つ仕事と計算する仕事

100%

ネットワーク待ち、ファイル処理、暗号処理などの内部経路は同じではない。OS の非同期機構やワーカープールを使うものがある。Promise で包むだけでは同期計算は外へ移らない。

async function slow() {
  // async でも、このループ中は実行スレッドを占有する
  let total = 0;
  for (let i = 0; i < 1_000_000_000; i++) total += i;
  return total;
}

CPU 負荷はアルゴリズムの改善、分割、Worker Threads、別プロセスなどで扱う。await Promise.resolve() の反復も、タイマーや I/O に公平な実行機会を保証する方法ではない。

Promise と await

Promise は将来の成功値または失敗を表す。await はその関数の継続を待機させるが、他のタスクの完了順序まで固定しない。

const user = await fetchUser();     // 依存があるので直列
const orders = await fetchOrders(user.id);

const [profile, settings] = await Promise.all([
  fetchProfile(), fetchSettings(), // 互いに独立しているので並行に開始
]);

Promise.all は1件が reject すると結果も reject する。しかし、残りのリクエストを自動ではキャンセルしない。全結果が必要なら Promise.allSettled を検討する。

同時実行数を制限する

1万件の URL に一度に Promise.all(urls.map(fetch)) を実行すると、接続数、メモリ、相手のレート制限を圧迫する。キューとワーカー数で開始件数を制限する。

async function forEachConcurrent<T>(
  items: readonly T[],
  concurrency: number,
  work: (item: T) => Promise<void>,
): Promise<void> {
  if (!Number.isInteger(concurrency) || concurrency < 1) {
    throw new Error("Invalid concurrency");
  }
  let next = 0;
  let stopped = false;
  async function worker() {
    while (!stopped && next < items.length) {
      const item = items[next++]!; // await より前に次の項目を確保
      try {
        await work(item);
      } catch (error) {
        stopped = true; // 新規の開始を止める。実行中の仕事は止まらない
        throw error;
      }
    }
  }
  const results = await Promise.allSettled(
    Array.from({ length: Math.min(concurrency, items.length) }, worker),
  );
  const failure = results.find(r => r.status === "rejected");
  if (failure?.status === "rejected") throw failure.reason;
}

この例は実行中の仕事が完了してから失敗を返す。中止を依頼したければ work にシグナルを渡す契約も必要だ。

キャンセルと共有状態

AbortController は対応する API へ中止を依頼する仕組みで、任意の計算を強制停止しない。Promise.race でタイムアウトを返しても、負けた処理は残りうる。

1スレッドでも、await の前に読んだ残高が後で同じとは限らない。複数リクエストが交互に進むため、共有データの更新には トランザクションや条件付き更新が必要になる。

確認するのは「async が付いているか」ではなく、どこで待ち、どこで CPU を使い、何件が進行中で、誰が終了させるかだ。

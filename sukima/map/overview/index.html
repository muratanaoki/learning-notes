Sukima Studyの全体像とコードの読み方

iOS・Android・Webと共通API・教材制作の役割を分け、実装へたどる。

更新: 2026-09-27

実装確認: 2026-09-27 · monorepo 09a19a3
記事内の実装パスは、この時点のmonorepoを参照します。

Sukima Studyは、日本語話者が短い時間で英語を学ぶサービス。iOS・Android・Webが共通の教材とAPIを使う。1リールの5フレーズを音声・解説・リスニングで繰り返し学び、発音テストはネイティブアプリで行う。

利用先実装境界
iOSSwiftUI、iOS 26.0以上録音・バックグラウンド再生などをAppleの仕組みへ接続
AndroidKotlin / Jetpack Compose、Android 14以上戻る操作・音声認識・再生通知をAndroidへ接続
WebNext.js登録前から教材を閲覧・再生。発音はアプリへ案内

複数端末に対応していても、現在の学習Contextはgeneral-english / ja-JP / phrase。型が複数教科に拡張できることと、他の教材が提供済みであることは別。

この章は実装を理解するための学習ノートであり、仕様の正本ではない。記事とコードが違う場合はコードを確認する。運用コマンドは各プロジェクトのREADMEを参照する。

どこで何が動くか

生成ツールが使うAIと、アプリの実行時処理は別物。ユーザーがリールを開くたびに文章や画像を生成する構成ではない。

正本と配信用コピー

対象正本・所有者ほかの場所の役割
教材の英文・和訳・文法content/sukima-study/DBは検証済み教材の配信ミラー
画像・音声の制作素材同ディレクトリのMediaなどGCSは配信先、端末はキャッシュ
保存・学習完了APIのDB端末は表示と操作のために同期
認証アカウントFirebase AuthenticationAPIのUserはUIDで紐づく
インフラの土台infra/terraform/クラウド上の実体とstateを対応づける
画面挙動products/study/ios/・products/study/android/・products/study/web/docsと学習ノートは説明

iOSのResourcesはbundle資源や設定を置く場所。教材JSON・教材画像・教材音声をそこへコピーして配布する方式ではない。

おすすめの読み順

段階答えたい問い入口
教材JSONがどう1つのリールになる？教材の単位と版 → 実物を追う
アプリ共通契約を各端末でどう扱う？iOS・Android・Web
API・DB保存ボタンの後で何が起こる？APIの順路
開発・配信localからprodへ何を移す？環境とローカル開発
参照特定のファイルや表だけ調べたいJSON早見表・DB早見表

最初から列一覧を暗記しない。「リールを開く」「保存する」など1つの操作を選び、入力→変換→保存先→表示の順に追う。

目的から実コードを選ぶ

パスはすべてリポジトリルート基準。

知りたいこと最初に開くファイル
起動・SDK初期化products/study/ios/SukimaStudy/App/SukimaStudyApp.swift
タブ・画面遷移・ミニプレイヤーproducts/study/ios/SukimaStudy/App/MainTabView.swift
教材取得と版の固定products/study/ios/SukimaStudy/Services/RemoteContentProvider.swift
リクエストの入口products/study/api/src/content/content.controller.ts
教材の変換・検証products/study/api/scripts/content-contract.ts
DBの関係・制約products/study/api/prisma/schema.prisma
クラウドへの反映順products/study/api/scripts/release/release.sh

pipelines/のSNS制作基盤やproducts/print/のポスター用Webは同じモノレポの別チャネル。アプリ教材のreelとSNS動画のsectionは別のデータ構造なので、名前が似ていても同じ型と考えない。

読めたか確認

「和訳を直す」「保存順を変える」「ミニプレイヤーの位置を変える」の3つについて、それぞれ正本がどこか説明できれば、全体地図はつかめている。

配列と連結リスト

データをメモリにどう並べるかで、速い操作と遅い操作が入れ替わる

更新: 2026-09-06

同じ「値の並び」でも、メモリへの置き方は大きく2通りある。ぎっしり詰めて置く（配列）か、バラバラに置いて矢印でつなぐ（連結リスト）か。この置き方の違いが、「n番目を読む」「途中に挿入する」といった操作の速さをそっくり入れ替える。どちらが良いではなく、得意が逆という話。

並べ方を見比べる

添字を選んでアクセスすると、配列は直接到達し、リストは先頭から参照を辿る。操作を「先頭へ99を挿入」に切り替えると、配列は既存要素を右へずらし、リストは新ノードの next と head を付け替える。要素数を3・5・8個へ変え、必要な手数を比べる。

得意な操作を入れ替えて比べる

末尾へのアクセスはどちらが短い？ 先頭への挿入ではどうなる？ 要素数を変えて必要な手数を比べる。

手順 1 / 5

配列：連続した領域

[0]17
[1]42
[2]8
[3]31
[4]26

添字アクセス：0回（O(1)）

連結リスト：次への参照を持つノード

head17→ 次
ノード142→ 次
ノード28→ 次
ノード331→ 次
ノード426→ null

ノード訪問：0個（この添字まで 3 回たどる）

開始前。配列と連結リストに同じ値が入っている。

固定幅要素と、head が既知の単方向リストの模型。配列の追加領域・新ノードは確保済みとし、再確保やキャッシュの影響は省く。JavaScript の Array の内部実装そのものではない。

配列：連続していることが武器

配列 要素をメモリ上に隙間なく連続して並べたデータ構造。i番目のアドレスを計算で一発に出せる。 は要素をメモリに隙間なく並べる。だから i 番目のアドレスは 先頭アドレス + i × 要素サイズ で即計算でき、どこでも O(1) で読める（ ランダムアクセス 添字から一発で要素に届く性質。配列やハッシュの強み。 ）。

代償は挿入・削除。途中に入れると、後ろの要素を全部ずらす必要があって O(n)。

連結リスト：つなぎ替えが武器

連結リスト 各要素（ノード）が「値」と「次のノードへの参照」を持ち、鎖のようにつながったデータ構造。 はノードがメモリ上でバラバラでよく、各ノードが「次はここ」という ポインタ 他のデータが置かれているメモリ上の位置（アドレス）を指し示す値。 を持つ。挿入・削除は必要な参照が揃っていればO(1)。単方向リストで削除するには通常、対象だけでなく直前ノードへの参照も必要になる。

代償はアクセス。k 番目に行くには先頭から矢印を k 回辿るしかなく O(n)。アドレス計算では飛べない。

得意・不得意はちょうど逆

操作配列連結リスト
i 番目を読むO(1)O(n)
先頭に挿入O(n)O(1)
途中に挿入（場所が既知）O(n)O(1)
メモリ連続・密飛び飛び・ポインタ分の余分

「よく読む・末尾中心」なら配列、「先頭や途中で頻繁に付け外し」ならリスト。実際には配列（動的配列）が既定で強く、リストは特定の場面で効く。

実装と言語の前提

この説明は固定長要素の配列とノード型のリストのモデル。JavaScriptのArrayが常に数値を物理的に隙間なく置くとまでは保証しない。オブジェクト参照の配列なら、連続するのは参照であって参照先の本体とは限らない。

動的配列は容量が足りなくなると拡張するため、末尾追加1回がO(n)でも、連続した追加の償却計算量はO(1)にできる。リストはポインタ追跡と局所性の弱さ、ノードごとの割り当てが実時間へ影響する。

確認：先頭からk番目を探して削除するリスト操作はO(1)だろうか？ 場所を探すO(n)も含めて数える。
